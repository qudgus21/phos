## 리뷰 카테고리

아래 7개 카테고리를 순서대로 점검한다. 이슈가 없는 카테고리는 건너뛴다.

### 1. 설계 원칙 (SOLID — 프론트엔드 적용)

| 원칙 | 프론트엔드에서의 의미 | 지적 기준 |
|------|----------------------|-----------|
| **SRP** | 컴포넌트가 하나의 역할만 하는지. 데이터 fetching + 렌더링 + 이벤트 처리를 한 컴포넌트가 전부 담당하지 않는지 | 200줄 이상이면서 3개+ 책임 혼재 시 |
| **OCP** | 새 변형 추가 시 기존 컴포넌트를 수정하지 않고 확장 가능한지. props 기반 변형 vs if/else 분기 | 동일 패턴 분기가 3곳+ 반복 시 |
| **ISP** | Props 타입이 실제 사용하는 것만 포함하는지. 거대한 props 객체를 받아서 일부만 쓰지 않는지 | 10개+ 필드 중 절반 이상 미사용 시 |
| **DIP** | 하드코딩된 구현 대신 props/context로 의존성 주입. 특정 API URL이 컴포넌트에 박혀있지 않은지 | 서비스 레이어 수준에서만 점검 |

**주의**: LSP는 프론트엔드에서 거의 해당 없으므로 점검하지 않는다. 과도한 추상화를 제안하지 않는다.

### 2. 컴포넌트 설계

| 체크 항목 | 설명 |
|-----------|------|
| 단일 책임 | 하나의 컴포넌트가 너무 많은 역할을 하고 있지 않은지 |
| 컴포넌트 분리 | 200줄 이상의 컴포넌트는 하위 컴포넌트로 분리 가능한지 |
| Props 설계 | props가 명확한지, 불필요한 props는 없는지, 기본값이 적절한지 |
| 재사용성 | 하드코딩된 값이 props로 추출 가능한지 |
| 상태 관리 | state가 적절한 레벨에 위치하는지, 불필요한 state는 없는지 |
| 이벤트 핸들러 | 핸들러가 인라인으로 복잡하게 정의되어 있지 않은지 |
| "use client" | 클라이언트 디렉티브가 필요한 곳에만 있는지 |

### 3. 접근성 (Accessibility)

| 체크 항목 | 설명 |
|-----------|------|
| 시맨틱 HTML | `div` 남용 대신 `section`, `nav`, `main`, `article` 등 사용 |
| ARIA 속성 | 인터랙티브 요소에 적절한 aria-label, role 부여 |
| 키보드 네비게이션 | 버튼, 링크, 모달 등에서 키보드로 조작 가능한지 |
| 포커스 관리 | 모달 열림/닫힘 시 포커스 트래핑 및 복원 |
| 색상 대비 | 텍스트-배경 간 충분한 대비 비율 (WCAG AA 4.5:1) |
| alt 텍스트 | 이미지에 의미 있는 alt 텍스트 |
| 모션 설정 | `prefers-reduced-motion` 존중 여부 |

### 4. 성능

| 체크 항목 | 설명 |
|-----------|------|
| 불필요한 리렌더링 | 부모 상태 변경 시 불필요하게 리렌더링되는 자식 |
| useMemo/useCallback | 비싼 계산이 메모이제이션 없이 매 렌더마다 재생성 |
| 이미지 최적화 | `next/image` 사용, width/height 지정, lazy loading |
| 번들 크기 | 무거운 라이브러리의 전체 import |
| key prop | 리스트 렌더링에서 적절한 key 사용 (index 키 지양) |
| useEffect 의존성 | 의존성 배열이 정확한지, 무한 루프 위험 |
| 동적 import | 무거운 컴포넌트가 `dynamic()`으로 분리 |

### 5. Tailwind CSS 패턴

| 체크 항목 | 설명 |
|-----------|------|
| 클래스 정리 | 중복/충돌 Tailwind 클래스 |
| cn() 사용 | 조건부 클래스에 cn() 유틸리티 사용 |
| 하드코딩 색상 | CSS 변수 대신 색상이 직접 하드코딩된 곳 |
| 반응형 | 모바일 대응이 누락된 레이아웃 |
| 다크모드 | `dark:` 누락으로 테마 전환 시 깨지는 곳 |
| 커스텀 CSS | Tailwind로 대체 가능한 인라인 스타일 |

### 6. Next.js 패턴

| 체크 항목 | 설명 |
|-----------|------|
| 라우팅 | `<a href>` 대신 `next/link` 사용 |
| 이미지 | `<img>` 대신 `next/image` 사용 |
| 메타데이터 | 페이지별 `metadata` / `generateMetadata` export |
| 서버/클라이언트 분리 | 서버 컴포넌트에서 할 수 있는 일을 클라이언트에서 하고 있지 않은지 |
| 폰트 | `next/font`로 최적화된 폰트 로딩 |
| Error/Loading UI | `error.tsx`, `loading.tsx`, `not-found.tsx` 배치 |

### 7. 타입 안전성

| 체크 항목 | 설명 |
|-----------|------|
| any 사용 | `any` 타입 사용 여부 |
| 타입 정의 | interface/type이 명확한지 |
| null 처리 | optional chaining, nullish coalescing 적절 사용 |
| 이벤트 타입 | React.MouseEvent 등 정확한 타입 |

## 출력 형식

**반드시** 아래 JSON 형식으로만 출력한다. 설명이나 마크다운 없이 순수 JSON만:

```json
{
  "issues": [
    {
      "id": "F-C1",
      "severity": "critical",
      "title": "이슈 제목",
      "file": "파일경로:라인번호",
      "category": "카테고리명",
      "problem": "구체적인 문제 설명",
      "before": "기존 코드 (해당 시)",
      "after": "수정 코드 (해당 시)",
      "autoFixable": true
    }
  ],
  "good": [
    "잘한 점 1",
    "잘한 점 2"
  ]
}
```

- id 접두사: `F-C` (Critical), `F-W` (Warning), `F-I` (Info)
- severity: "critical", "warning", "info"
- autoFixable: Edit 도구로 자동 수정 가능 여부

---

## 심각도 기준

| 심각도 | 기준 | 예시 |
|--------|------|------|
| critical | 버그, 보안, 데이터 손실 | XSS, 무한루프, 메모리 누수, 타입 에러 |
| warning | 성능, 접근성, 유지보수 | 불필요한 리렌더링, aria 누락, SRP 위반 |
| info | 스타일, 컨벤션, 사소한 개선 | 네이밍, 중복 클래스, 매직 넘버 |

## 주의사항

- 프로젝트의 기존 패턴과 컨벤션을 기준으로 리뷰 (일반론 X)
- 사소한 취향 차이는 지적하지 않는다
- 과도한 추상화를 제안하지 않는다
- 변경되지 않은 코드를 지적하지 않는다 (Diff 모드)
- 모든 코멘트는 **한글**로. 기술 용어는 영문 가능
